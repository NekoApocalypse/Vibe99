# Vibe99 0.8.0：点开文件阅读，链接始终指向当前内容

这次 Windows 发布给 Vibe99 增加只读 Markdown pane，并修复 URL 打开和输出更新后的旧链接误触。终端中的 Markdown 路径单击打开；HTTP(S) 链接保留 Ctrl+单击。新文档只在创建时插入来源右侧，此后独立拖动、聚焦和关闭；原有前台不透明、后台按顺序半透明叠加的布局保持不变。

文档支持代码高亮、公式、Mermaid 和文件图片。简单既有 SSH 可自动识别，内部建立独立文件连接，不增加终端或安装常驻服务；关闭来源后文档仍可读取和刷新。复杂／嵌套 SSH 或缺少目录时需要显式位置，要求已有非交互认证和 known_hosts，远端需要 Linux 和 Python 3。文档不会随重启自动恢复；定位期间连续点击只保留最后一个待处理请求，文档内链接在当前预览导航。

鼠标恢复仍只作用于需要恢复的 pane；正常 PowerShell 提示符不再意外还原光标。**完整的睡眠／tmux／agy 双重滚轮现象仍未复现。当前安装包仍未签名。** 本次发布不关闭用户正在运行的应用，也不自动覆盖已安装版本。

新发现的旧链接问题来自 xterm 6.0.0 缓存：指针离开链接后，同行内容变化可能仍激活旧目标。补丁只使过期缓存失效，保留正常缓存与点击行为。`scripts/patch-xterm-link-cache.cjs` 固定版本并验证原始文件哈希，在安装和构建时处理两种模块格式；没有在应用代码中访问私有字段、伪造鼠标移动或延迟点击。[维护说明](../xterm-link-cache.md)记录了源码等价修改和移除条件。许可证随两个安装包分发。

**发布验收：**

- 19 项 Node、33 项 Rust、9 项桥接单元测试通过；48 个真实鼠标回归覆盖两种 xterm 格式、同行空白、原先无链接、同格返回、立即点击和持续悬停。普通 pane、文件链接、恢复、PowerShell 5.1／7 的回归通过。
- 最终生产程序在真实 SSH 中通过绝对／相对 Markdown、空格与中文路径、文件超链接、HTTP 普通链接和 HTTPS 超链接；实际 Windows opener 返回成功。旧 Markdown 被 HTTPS 替换后点击打开新 URL，没有创建旧文档。
- 关闭来源后三个文档（两个远端、一个本地）仍在，修改远端文件后能刷新；六个测试工作区全部关闭，配置按原字节还原，既有应用进程未变。协议测试另验证约 60 秒无心跳会清理自有任务和目录。

证据位于 `artifacts/release-0.8.0-native-links.log`、`native-companion-release-0.8.0-results.json`、`release-0.8.0-link-cache.log` 和 `release-0.8.0-ssh-protocol.log`。最终实测程序 SHA256 为 `cd9fcb45c37467b96c8e40332595dc1554bff7a749f5ca25c165b7ef440a80ce`；Windows 安装包与校验和位于 `artifacts/Vibe99-0.8.0/`，MSI 产品版本与内嵌程序元数据已验证。发布按用户授权推进，GitHub 的 Windows 发布流程也会验证链接回归与单元测试。
